# DESIGN — 게임 설계 (GDD)

> 확정분만 기록한다. 스튜디오 📄 문서 탭에서 열람.

## 화면 구성과 플로우

| 화면 | 내용 | 전환 |
|---|---|---|
| 타이틀 | 로고(알바킹) + "출근하기" 버튼 + 태그라인. 버튼 1개 원칙 — 클릭 3초 내 인게임 | 출근하기 → 게임 루프 |
| 게임 루프 | 지시어(0.8초, 화면 중앙 대형) → 플레이(5~10초) → 판정 연출(0.6초) → 다음 레벨 | 목숨 0 → 게임오버 |
| 게임오버 | "근무 종료!" + 점수 + 사장님 평가서(P6: LLM, 폴백 뱅크) + AI 스태프롤 3줄 | 재출근 → 게임 루프 |

- **총 30라운드 완주제**: 라운드 1~10 = 난이도 0, 11~20 = 1, 21~30 = 2 (**10라운드마다 상승** — 테마 10종이 티어마다 한 번씩). 30라운드 클리어 = "만근 달성!" 완주 화면.
- 레벨 배치: 테마 교차 순환(같은 템플릿 연속 금지). 난이도 상승 시 "난이도 상승 — 새 변형 투입" 배너.
- 목숨 3개, 실패해도 다음 라운드로 전진(점수만 손해). 콤보: 연속 성공 카운터.
- 점수: 클리어 100 + 남은 시간 보너스. 퍼펙트(제한시간 40% 이상 남김) 시 가산.
- **기믹 원칙: 템플릿은 3종이지만 테마마다 상황에 맞는 기믹 1개 이상, 그리고 기믹은 1라운드부터** — 초밥 "세트 완성"(샤리 슬롯당 1개), 김밥·편의점 "주문표 + 페이크 재료"(오답 -0.5초 + 플래시), 카페 "홀드 게이지", 치킨 "왕복 게이지", 붕어빵 "반복 타이밍".
- **튜토리얼 = 1라운드 한정, 타임스탑 + 스포트라이트**: 1라운드는 김밥(주문 순서 기믹 보유)으로 시작 — 잡기 → 놓기 → 주문 순서까지 3스텝을 한 번에 안내하고 끝. 2라운드부터 가이드 없음(조작이 새로운 테마는 지시어 아래 한 줄 힌트로 대체). 봇 QA는 가이드 off 옵션.
- **테마 순환(확정)**: 김밥(A)→카페(B)→초밥(A)→택배(C)→편의점(A)→치킨(B)→빵집(A)→세차(C)→붕어빵(B)→노래방(C) — 같은 템플릿 연속 없음, 티어 경계 순환 포함.

## 캔버스·조작 규격 (확정)

- **논리 해상도 720×1280 (9:16 세로)** — 엔진 좌표계는 논리 px. CSS transform scale로 화면에 맞춤, 데스크톱은 중앙 정렬.
- 입력: Pointer Events 단일 경로(탭/드래그 공용). `touch-action: none`.
- 루프: 고정 타임스텝 60Hz 누산기 — 엔진 tick은 순수 함수(렌더 무관·시드 RNG) → 봇 QA(P5)가 같은 tick을 호출.

## 테마별 게임 진행 (10종)

| # | 알바 | 기믹 (전부 1라운드부터) | 조작 | 실패/페널티 | 난이도 파라미터 |
|---|---|---|---|---|---|
| 1 | 초밥집 | **어종 매칭** — 샤리마다 요구 재료(참치/연어/계란)가 다름, 슬롯 위 칩 표시 | 맞는 재료를 맞는 샤리에 드래그 | 오매칭 페널티 / 시간 초과 | 세트 수 2→4, 시간 ↓ |
| 2 | 김밥천국 | **주문 순서** — 번호 순서대로만 + 페이크 재료 | 재료를 김밥에 순서대로 드래그 | 순서 위반·페이크 페널티 | 재료 수 2→3, 시간 ↓ |
| 3 | 편의점 | **수량 주문** — 같은 상품 ×n + 페이크 상품 | 주문 수량만큼 스캐너에 드래그 | 페이크 페널티 | 총수량 3→4, 시간 ↓ |
| 4 | 빵집 | **수량 주문** — 같은 빵 ×n + 페이크 빵 | 주문 수량만큼 트레이에 드래그 | 페이크 페널티 | 총수량 3→4, 시간 ↓ |
| 5 | 카페 | **홀드 게이지 + 잔마다 다른 적정선** | 꾹 눌러 채우고 구간에서 놓기 | 넘침 자동 미스 / 이탈 페널티 | 잔 수 2→4, 구간 ↓, 속도 ↑ |
| 6 | 치킨집 | **왕복 게이지 + 회마다 다른 구간** | 구간 진입 순간 탭 | 이탈 페널티 | 마리 수 2→4, 구간 ↓, 속도 ↑ |
| 7 | 붕어빵 | **반복 상승 게이지 + 회마다 다른 구간** | 타이밍 탭 | 이탈 페널티 | 개수 2→4, 구간 ↓, 속도 ↑ |
| 8 | 택배 상하차 | **이동 타깃 연타** — 3타마다 박스가 도망 | 박스 연타 | 목표 미달 | 목표 12→22, 시간 ↓ |
| 9 | 세차장 | **문지르기** — 문지른 거리만큼 거품 소모 | 스와이프 | 잔여 거품 | 거품 수·내구 ↑, 시간 ↓ |
| 10 | 노래방 | **좌우 교대 연타** — 같은 쪽 연타 효율 65%↓, 게이지 상시 감쇠 | L/R 번갈아 탭 | 게이지 미달 | 이득 ↓, 감쇠 ↑, 시간 ↓ |

## 무대(스테이징) 정합성 — ADR-009

게임 화면은 "알바가 자기 작업대를 내려다보는 1인칭"이라는 하나의 무대다.

- **배경 구도 규격**: 하단 40~45% = 빈 연속 작업 표면(테마별: 김밥 조리대 / 초밥 도마 / 카페 바탑 / 편의점 계산대 / 빵집 작업대 / 치킨 튀김 스테이션 / 붕어빵 철판 / 창고 작업 구역 / 세차 바닥 / 노래방 테이블), 상단 = 저대비 가게 컨텍스트. 사람·손·텍스트 금지.
- **레이아웃 규칙**: 타깃(드롭존·소품)은 표면 밴드(y≥~700)에, 재료 줄은 y~1060(표면 위 손앞) — 어떤 오브젝트도 공중에 뜨지 않는다.
- 게이지·카운터 등 추상 UI는 표면 하단(y~850+)에 겹치되 반투명 패널로 "UI임"을 명시.

## UI·화면 설계 (퀄리티 비협상 원칙)

> AI로 만든다고 퀄리티가 내려가면 의미가 없다 — **UI·화면 요소 전부가 발주·검수 대상**이다. 대역(SVG)은 개발용일 뿐, 최종 화면은 골든 톤(ADR-008)의 실아트로 교체된다.

| 화면 | 구성 요소 | 에셋 슬롯 | 텍스트(texts.json) |
|---|---|---|---|
| 타이틀 | 배경 일러스트 + 심볼 + 워드마크(코드 렌더) + 시작 버튼 + 태그라인 | title-bg, logo-symbol, ui-button-frame | title-name, title-start, title-tagline |
| 인게임 HUD | 목숨(3) · 라운드(n/30) · 점수 · 타이머 바 · 주문표(기믹 시) · 콤보 | ui-life, ui-timer-frame, ui-order-panel | sys-round, order-label, sys-combo |
| 판정·연출 | 지시어 대형 표시 · 퍼펙트/실패 플래시 · 난이도 상승 배너 · 오답 페널티 비네트 | (연출은 코드) | instr-*, sys-perfect, sys-fail, sys-levelup |
| 게임오버/완주 | 패널 + 점수 + 사장님 평가서(P6) + AI 스태프롤 3줄 + 재출근 | ui-panel, ui-boss | over-*, complete-* |

- 모든 화면은 논리 720×1280 그리드 위에서 설계. UI 에셋 발주 시 **화면 목업 컨텍스트(shots)** 를 첨부해 "화면 안에서" 검수한다.
- 대역→실아트 교체 판단은 스튜디오 이미지 검수(criteria.image) + 게임 탭 화면 검수의 이중 게이트.

## 레벨 JSON 스키마 (초안)

```json
{ "id": "sushi-d2-01", "template": "drag", "theme": "sushi", "difficulty": 2,
  "timeLimit": 4800, "params": { "itemCount": 2, "fakeItems": 1 } }
```

사다리 풀(P5): Claude가 대량 생성 → 봇 전수 검증·서열화 → 적응 선택기가 스킬 점수에 맞는 레벨을 선택(ADR-001).

## 텔레메트리 (게임오버 평가서 입력, P6)

테마별 {시도, 성공, 퍼펙트, 평균 클리어 시간, 실패 유형}, 최고 콤보, 최다 실패 테마 — 로컬 수집만, 외부 전송 없음.

## 확정

- 장르: 알바 체험 마이크로게임 연발 (레벨당 5~10초, 즉시 이해 가능한 한 단어 지시어)
- 실패 처리: 목숨제 + 점수제 (실패해도 전진 — 심사자 콘텐츠 노출 극대화)
- 난이도: EWMA 스킬 점수 + 목표 성공률 70~80% 제어기 → 사전 검증된 사다리 풀에서 선택 (ADR-001)
- 템플릿 3종: A 드래그&드롭 / B 타이밍 탭·게이지 / C 연타·스와이프 — 템플릿당 스킨 3~4개
- 코어 규칙: 게임 로직은 렌더와 분리 (순수 TS 모듈 · 고정 타임스텝 · 시드 RNG) — 봇 QA·스튜디오 프리뷰의 전제
- 화면: 세로형 중심 반응형 캔버스, 데스크톱 중앙 정렬, 탭/드래그 공용 조작
- 텍스트: 게임 내 모든 카피는 `pipeline/texts.json` 단일 소스 — 이미지에 굽지 않고 코드로 렌더, 스튜디오에서 검수
