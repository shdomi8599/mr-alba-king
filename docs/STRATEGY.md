# 알바킹 (mr-alba-king) — NAN 2026 사전 과제 전략 (최종)

전제: 1인 개발 / 웹(React+TS) / 제출물: 빌드+소스(GitHub Pages 링크, 커밋 기록 유지), 30~60초 실플레이 영상, 게임 소개 PDF, AI 활용 기술 문서 PDF. (팀원 롤 기술서는 1인 참가로 생략 대상.)
**일정 관리는 디렉터 소관.** 이 문서는 무엇을·어떤 순서로·어떤 의존성 위에서 만드는지만 정의한다.

---

## 0. 한 줄 전략

**"AI를 부하 직원(알바)처럼 지휘한 디렉터"를 게임·커밋·문서·영상 4개 매체에서 일관되게 증명한다.**
게임의 소재(알바 체험)와 개발기(AI 알바 인사관리)가 하나의 은유로 묶인다.
런타임 AI는 체감이 확실한 한 곳(게임오버 평가서)에만 배치하고, 나머지 AI는 빌드타임 공정(아트·오디오·레벨 생성·QA 봇)에 배치한다. 이 "선택적 배치" 자체가 디렉터 서사다.
그리고 이번 파이프라인은 tidy-up의 원칙(골든 레퍼런스 앵커, 발주→검수→재발주, 스테이징→승격)을 계승하되 **구현을 한 단계 위로 재설계**한다(§8) — "AI의 다음 단계를 설계"하는 인재상에 대한 실물 답안이 곧 이 파이프라인이다.

## 1. 기존 3안에 대한 결론

### 1-1. 아트 에셋 전량 AI 생성 — 채택 (만장일치)

- **골든 레퍼런스 승인이 최우선 크리티컬 패스.** 초밥 스티커 1장 승인 → 앵커 고정. 이후 모든 생성이 여기 앵커.
- 게임 개발은 **SVG 대역 에셋으로 선행** — 아트가 개발을 절대 블로킹하지 않게. manifest 기반 드롭인이라 교체 무중단.
- 발주는 **배치 단위 고정**(1차: 수직 슬라이스+템플릿 A·B / 2차: 나머지 스킨+강화 변형+UI). 배치당 **20% 여분 발주**(생성 폐기율 20~30% 반영). **리터치는 별도 1슬롯만** — 리터치 블랙홀 봉쇄.
- 주의: 음식·손·도구가 ref 1장으로 안 잡히면 카테고리별 ref 추가 승인(반나절 예산). 텍스트는 이미지에 굽지 않는다. 모바일 오디오 언락·프리로드는 코어 슬라이스 단계에서 확인.
- 발주 데이터 자체가 제출 요건("AI 대상 주요 프롬프트·지시 사항")의 1차 증거. "외부 에셋 0"으로 출처 항목 자동 클린.

### 1-2. AI 난이도 QA·밸런스 — 채택: 헤드리스 봇 시뮬레이터 + Claude 밸런스 리포트

- 반응속도 페르소나 3종(상급 200ms / 중급 350ms / 초보 500ms + 오차 분포) 봇이 게임 로직을 Node 헤드리스로 수천 판 시뮬레이션 → 레벨별 클리어율 CSV → Claude가 "레벨 7 클리어율 12%는 급락, 제한시간 +0.4초 권고" 식 패치 제안 → **디렉터가 승인/반려 후 JSON 반영·커밋**.
- **1일 하드 타임박스. 초과 시 즉시 폴백**: 수동 플레이 로그를 Claude가 분석.
- 봇 정교화 금지(반응 지연 분포 수준에서 멈춤). 절대값 불신 — **레벨 간 상대 서열용**으로만, 본인 실플레이로 교차 검증.
- **성립 전제(비협상)**: 코어 설계에서 **게임 로직을 렌더와 분리(순수 TS 모듈, 고정 타임스텝, 시드 RNG)**. 봇 QA·사다리 풀 검증·스튜디오 인컨텍스트 프리뷰 전부의 전제.

### 1-3. 실시간 난이도 감지 → 상위 레벨 즉시 투입 — 채택하되: **사전 생성·검증 풀 + 온디바이스 적응 선택기. 런타임 LLM 레벨 생성은 기각.**

유저 체감은 원안 그대로(잘하면 그 즉시 더 어려운 신규 변형 투입). 구현만 다르다.

1. **감지**: 클리어 시간·정확도·연속 성공/실패 EWMA 스킬 점수, 목표 성공률 70~80% 유지 P-제어기, 조정 스텝 상한+히스테리시스. 외부 의존성 0.
2. **콘텐츠 풀**: Claude가 오프라인에서 템플릿×테마별 상위 난이도 변형 대량 생성 → **QA 봇 전수 검증·서열화한 60~100레벨 "사다리 풀"** 번들 포함.
3. **천장 폴백**: 최상위는 파라미터 외삽(속도·개수 스케일링)으로 무한 연장.
4. **연출**: "난이도 상승 — 새 변형 투입" 표기. **'AI 생성' 배지 금지** — 빌드·영상·문서 주장 일치.

**기각 근거**: 런타임 LLM 레벨 생성은 최대 단일 투자 대비 심사자의 1~2분 플레이에서 사전 생성 풀과 체감 구분 불가 + 프록시·키·장애가 심사 시점 리스크. 문서에는 트레이드오프 분석 + **"본선 48시간에서 런타임 생성으로 확장" 로드맵 1줄** — 기각 자체가 디렉터 서사.

**정직 표기 원칙(문서 신뢰의 기반)**: 결정적 알고리즘은 문서에서 AI라 부르지 않는다. 이 경계 선언이 있어야 진짜 LLM 기능까지 신뢰를 얻는다. 서술은 "런타임 LLM 전면 배제"가 아니라 "선택적 배치".

## 3. 차별화 한 방 (differentiator)

### 3-1. 사장님 알바 평가서 — 유일한 런타임 LLM (만장일치)

게임오버 화면에서 세션 텔레메트리 기반 개인화 LLM 리포트: **"초밥은 장인인데 김밥만 잡으면 손이 떨리네?"**
- 게임오버는 심사자가 100% 보는 화면이자 유일한 레이턴시 무풍지대("사장님이 평가서를 쓰는 중..." 2~3초 연출).
- **실행 순서 엄수**: (1) 템플릿 폴백 뱅크 먼저(빌드 시 LLM 사전 생성) — 이것만으로 출하 가능 (2) 프록시는 서버리스 함수 1개+환경변수 키+3초 타임아웃으로 제한 (3) **총 1일 하드캡** (4) 게이트 미통과 시 LLM 레이어만 컷 — 실격 리스크 0.
- 이 기능으로 "런타임 AI를 어디에 왜 배치/배제했는가" **의사결정 매트릭스 챕터** 성립: 평가서(개인화 필수→런타임) vs 레벨 풀(사전 검증 가능→빌드타임) vs 대사(조합 유한→빌드타임).

### 3-2. 근무 평가서 화면 + AI 스태프롤 3줄

같은 화면에 통합: "아트: Claude 발주 × codex 제작 (N장 발주, M장 반려)" / "QA: 가상 알바 12,000명 근무" — **숫자는 이벤트 스토어 실측값만.** 3줄 상한. 영상 엔딩 컷 재사용 → 게임·영상·문서 삼중 노출. 반려 수치의 당당한 공개 = 검수하는 디렉터의 자기 증명.

### 3-3. "AI 알바 인사관리" 메타 프레임 — 문서의 스킨

기술 문서 골격 완성 후 덮어쓰는 편집 레이어. AI를 직원으로 명명(아트알바 codex, 코딩알바 Claude Code, QA알바 시뮬레이터, 작곡알바 fal), 산출물을 채용공고·발주서·검수 리포트·반려 사유서로 편집. **각 서류 뒤 기술 원문(실제 프롬프트·커맨드) 병기는 타협 불가.** 프레임 작업 반나절 상한, 안 되면 표지+장 제목만 은유 적용.

## 4. 스코프 티어

**Stretch (게이트 통과 + 잔여 여력 시, 이 순서로)**
1. 실패 원인 결정적 분류(순수 룰) + 사전 생성 힌트 뱅크(태그당 10~20개, 12자 이내). 애매하면 생략.
2. 인게임 AI 메이킹 갤러리 — 폴백: 게임오버 "에셋 전량 AI 생성 N종, 발주 기록은 레포에" 한 줄+링크.
3. 사장님 잔소리·게임오버 문구 소량 — 평가서 폴백 뱅크 제작에 흡수.
4. 비전 QA — 레벨 딥링크만 먼저, 비전 패스는 여유 시 1회, 자동 수정 루프 금지.
5. 밸런스 오토튜너 — QA 봇이 순조로울 때만 반나절.

**Kill (확정 기각)**
- **런타임 LLM 레벨 디렉터+프록시**: 체감 델타 0 + 심사 시점 장애 표면. 트레이드오프 분석+본선 로드맵 1줄로 대체.
- **영상 전용 런타임 LLM 데모**: 빌드에서 재현 불가한 장면 = 신뢰 붕괴. 영상과 빌드는 같은 물건.
- **심사위원 전용 모드**: 조작 인상+분기 비용.
- **미니게임 DSL/엔진 공장**: 엔진이 게임을 잡아먹는 고전 실패 경로. 안전판은 템플릿×JSON+사다리 풀로 충분.
- **데일리 시프트·리더보드·스토리/컷신·모바일 앱 래핑·템플릿 4종째**: 심사자는 한 세션만 플레이.

**컷 순서 (압박 시 이 순서로만)**
1. 평가서 LLM 레이어 → 템플릿 평가서판
2. Stretch 전 항목
3. 미니게임 수 12→9→6 (**6개 절대 하한**)
4. QA 봇 → 수동 플레이 로그 Claude 분석
5. 실시간 감지 정교화 → 단순 연승/연패 계단
6. 스튜디오 확장 → 베이스(검수 큐+마크)만, 최악 시 정적 콘탁트시트
7. 템플릿 3종→2종

**절대 안 자르는 것**: 상시 배포 상태 / 첫 3게임 폴리싱 / 영상 전용 시간 / 문서 조립 전용 시간 / 커밋 이력 규율.

## 6. AI 역할 분담표 — 모든 공정은 "AI 제안 → 디렉터 승인" 게이트를 거친다

| 공정 | AI 담당 | 산출물 | 디렉터가 결정하는 것 |
|---|---|---|---|
| **기획** | Claude — 변형 아이디어, 난이도 사다리, 레벨 JSON 대량 생성, 카피(지시어·사장님 멘트·평가서 폴백 뱅크) | 레벨 JSON, 사다리 풀, 카피 뱅크 | 컨셉·템플릿 확정, 레벨 채택/반려, 카피 톤 |
| **개발** | Claude Code — 코드 작성·리팩터링·테스트 | 커밋 (Co-Authored-By) | 아키텍처, 코드 리뷰, 머지 |
| **아트** | codex — 발주 기반 생성(골든 레퍼런스 앵커) | 에셋 PNG | ref 승인, 채택/반려+사유, 재발주 |
| **오디오** | fal 단일 SDK — 다중 모델 경쟁(§9) | SFX 슬롯, BGM 루프 | 후보 A/B 즉결 선정, 승격 |
| **QA·밸런스** | 헤드리스 봇(페르소나 3종)+Claude 리포트 | 클리어율 CSV, 패치 제안 | 패치 승인/반려 후 커밋 |
| **런타임** | LLM — 사장님 알바 평가서 (유일) | 개인화 리포트(폴백 상시 대기) | 프롬프트·스키마 승인, 유지/컷 판정 |
| **문서** | Claude — 이벤트 스토어에서 PDF 조립 | 기술 문서·소개 문서 초안 | 최종 편집, 숫자 실측 대조 |

이 표가 기술 문서의 1페이지. 디렉터의 승인/반려는 전부 이벤트로 기록되어 "디렉터 반려 N건" 실측 숫자의 출처가 된다.

## 7. 파이프라인·스튜디오 — tidy-up의 원칙을 계승한 차세대 설계

**계승하는 원칙(느낌)**: 골든 레퍼런스 앵커 / 발주→검수→재발주 루프 / 스테이징→승격 / IP-safe 프롬프트 / 텍스트는 코드로.
**버리는 구현**: 카테고리별 셸 스크립트 난립(gen-*.sh 20여 개), md 규약과 사람 규율에 의존하는 일관성, 도구 간 단절(리뷰 서버↔생성기↔원장이 파일 규약으로만 연결), 수동 원장.

**새 구조 — 하나의 타입 시스템, 하나의 상태 머신, 하나의 스튜디오:**

1. **Order-as-Data**: 발주가 스크립트가 아니라 타입드 데이터. `{id, kind(sprite|bg|ui|sfx|bgm|level|copy), subject, spec, anchorRef, promptTemplate, attempts[]}`. 단일 CLI가 kind별 어댑터(codex 이미지 / fal 오디오 / Claude 레벨·카피)로 디스패치. 새 에셋 종류 = 스크립트 추가가 아니라 데이터 1건 추가.
2. **자산 생애주기 상태 머신 + 이벤트 소싱**: `draft → ordered → generated → in-review → approved | rejected(reason) → re-ordered`. 모든 전이가 이벤트 스토어에 append — **원장은 파생물이며 수동 기록이 없다.** 문서·스태프롤의 모든 숫자는 이벤트 쿼리 결과. tidy-up에서 규율로 유지하던 것을 구조가 강제한다.
3. **Manifest = 단일 진실 원천**: 승인된 에셋만 manifest에 진입, 게임은 manifest 타입으로만 에셋 참조(미승인 = 자동 플레이스홀더). 게임·스튜디오·파이프라인이 같은 타입 패키지를 공유 — 존재하지 않는 에셋 참조가 컴파일 타임에 잡힌다.
4. **스튜디오 = 게임 렌더러를 임포트하는 검수 앱** (로컬 전용, 레포 포함): 로직/렌더 분리 덕에 실제 게임 컴포넌트로 **인컨텍스트 프리뷰**(실배경·실스케일 + 0.5초 플래시 판독성 테스트 — 검수 기준이 곧 반려 사유 언어). 화면: 검수 인박스(생성됨 큐), 반려 사유 → **재발주 초안 자동 생성**(다음 배치에 포함), 레벨·QA 보드(클리어율 히트맵·이상치·딥링크 플레이·패치 diff 승인/반려), 오디오 A/B(다중 모델 후보 비교), 원장 대시보드(발주 N·반려 M·시뮬레이션 K판 라이브). 승인/반려 클릭 = 이벤트 append.
5. **문서 자동 조립**: 기술 문서 초안이 이벤트 스토어+orders에서 생성(`docs build` → md → PDF). 반려 갤러리·발주 원문·숫자 전부 쿼리. 최종 편집만 사람.
6. **스튜디오 스크린샷이 기술 문서의 "통제하는 디렉터" 시각 증거.** 파이프라인 설계 자체가 "AI의 다음 단계를 설계"의 실물 답안으로 문서 한 챕터를 차지한다.

**운영 원칙**: 스튜디오는 게임을 블로킹하는 순간 강등(컷 순서 6번). 도구가 게임을 잡아먹지 않는다 — DSL/엔진 공장 기각과 같은 원칙.

## 8. 오디오 파이프라인 결정

**결론: fal 단일 SDK 유지 + 모델 라인업 상향 + 다중 모델 경쟁 배치.**

- **구조는 tidy-up 방식 계승이 옳다**: 키 1개(FAL_KEY), 단일 SDK로 전 모델 접근, 검증된 후처리(ffmpeg 심리스 루프 폴드, ogg 변환, 스테이징→승격). 이 후처리 자산은 그대로 가치가 있다 — 단, §7 구조(order/어댑터/이벤트)로 재구현.
- **BGM — 다중 모델 경쟁으로 상향**: 2026년 8월 현재 fal에서 Lyria 3 Pro(인스트루멘털 리더보드 상위, ~$0.04/곡), Stable Audio 2.5/3(Community License — 산출물 소유·상업 이용 가능, 연매출 $1M 미만), MiniMax Music 2.6(상업 이용 가능), CassetteAI(초고속·로열티프리)까지 한 SDK로 호출 가능. **한 배치에서 모델 3종 × 후보 2곡 = 6후보를 뽑아 스튜디오 A/B로 즉결** — 단일 모델 재발주 왕복보다 빠르고 품질 상한이 높다. 알바킹 톤: 경쾌·코믹·긴박 가속(난이도 상승용 템포업 버전 포함).
- **SFX — ElevenLabs Sound Effects v2(fal 경유) 유지**: 0.2~1.6초 UI/액션 효과음에서 검증됨. 템플릿별 슬롯(start/success/fail/perfect)+테마 액센트.
- **Suno·Udio 계열은 기각**: 품질 최상위지만 상업 라이선스가 미정리 상태(학습 데이터 소송 진행 중). 이 대회는 수상작 사업화 우선협상권(4개월)이 걸려 있어 라이선스 클린이 우선. **이 판단 자체를 기술 문서의 라이선스 챕터에 기록** — 라이선스까지 검수하는 디렉터의 증거.
- IP-safe 프롬프트 원칙 유지(스튜디오/작곡가 이름 금지, 분위기로만 기술).

## 9. 시작 전 운영 체크리스트

## 10. 문서·커밋 거버넌스 (참가 제출을 위한 규율 — P0에서 설치, 소급 불가)

**문서 체계 (`docs/`)**
- `STRATEGY.md` — 본 문서(전략·스코프의 단일 진실).
- `DESIGN.md` — 게임 설계(GDD): 템플릿 스펙, 레벨 JSON 스키마, 난이도 모델, 텔레메트리 스키마.
- `PIPELINE.md` — §7·§8 파이프라인 상세 설계와 사용법.
- `DECISIONS.md` — ADR-lite: 중요한 결정마다 {날짜, 결정, 근거, 기각한 대안} 5줄. 기술 문서의 의사결정 챕터 원료.
- `SUBMISSION.md` — 제출물 4종 체크리스트와 조립 절차.

**커밋 규율**
- 컨벤션: `type(scope): 요약 — order#/결정# 참조` (예: `feat(art): 초밥 스프라이트 3종 — order#12, 2회 반려 후 채택`). 간단한 commit-msg 훅으로 형식 강제.
- 발주 데이터와 산출 에셋은 **같은 커밋에**. 페이즈 완료마다 태그(`p1-vertical-slice` 등).
- AI 작성 커밋은 Co-Authored-By 유지. LFS 금지, 정규화된 최종 에셋만 커밋(원본·폐기물은 이벤트 스토어 참조로).
- 커밋 로그만 읽어도 발주→생성→반려→채택 스토리가 재구성되도록 — **커밋 기록 유지 요건을 득점 요소로 전환.**

**증거 축적 (문서가 저절로 써지는 조건)**
1. orders 데이터 전부(프롬프트 원문·앵커 ref·규격) — 에셋과 같은 커밋.
2. 반려 기록: 리사이즈본 + 사유 한 줄(게임플레이 요구사항 언어).
3. 이벤트 스토어 — 모든 공정 전이 자동 기록(수동 원장 없음).
4. 골든 레퍼런스 원본 + 앵커 전/후 비교컷.
5. QA: 클리어율 CSV, 패치 전/후 곡선, Claude 판정 프롬프트·제안 원문, 승인 커밋 해시.
6. 레벨 생성 프롬프트 + 생성 diff 커밋, 봇 전수 검증 로그(시뮬레이션 총 판수 = 스태프롤 숫자 출처).
7. 오디오: 모델별 발주 프롬프트, 후보 비교·선정 기록, 라이선스 판단 기록.
8. 평가서: 시스템 프롬프트+출력 스키마+폴백 설계도 — 런타임 LLM 의사결정 매트릭스 재료.
9. 기각 결정 기록: 런타임 레벨 생성 트레이드오프 + 본선 확장 로드맵, "결정적 알고리즘은 AI라 부르지 않는다" 경계 선언, 게이트·다운스코프 로그.

**최종 검증 원칙**: 문서의 모든 주장에 커밋 해시 또는 레포 경로. 모든 숫자는 이벤트 스토어 실측값. 영상·빌드·문서 세 매체의 주장이 어긋나는 문장 0건 확인 후 제출.
