# DECISIONS — ADR-lite

> 형식: 날짜 / 결정 / 근거 / 기각한 대안. 기술 문서의 의사결정 챕터 원료. (STRATEGY.md §10)

## ADR-001 · 2026-08-01 · 실시간 레벨 공급 = 사전 생성·검증 풀 + 온디바이스 적응 선택기
- **결정**: 난이도 적응은 클라이언트 결정적 알고리즘(EWMA 스킬 점수 + 목표 성공률 70~80% 제어기), 콘텐츠는 Claude 오프라인 대량 생성 → QA 봇 전수 검증한 사다리 풀을 번들 포함.
- **근거**: 심사자의 1~2분 플레이에서 런타임 생성과 체감 구분 불가, 프록시·키·장애는 심사 시점 리스크.
- **기각**: 런타임 LLM 레벨 생성(+프록시) — 본선 48시간 확장 로드맵으로만 유지.

## ADR-002 · 2026-08-01 · 런타임 LLM은 "사장님 알바 평가서" 단 한 곳
- **결정**: 게임오버 화면 개인화 평가서만 런타임 LLM. 폴백 뱅크 선행, 서버리스 프록시 1개+3초 타임아웃, 실패 시 폴백으로 완전 동작.
- **근거**: 게임오버는 100% 노출 + 유일한 레이턴시 무풍지대, 텔레메트리 크로스 참조는 LLM이어야만 하는 실제 이유.
- **기각**: 상시 LLM 대사·힌트(비용/장애 표면 대비 체감 미미).

## ADR-003 · 2026-08-01 · 정직 표기 원칙
- **결정**: 결정적 알고리즘은 문서·게임·영상 어디서도 AI라 부르지 않는다. 'AI 생성' 배지 금지. 세 매체(빌드·영상·문서)의 주장 일치를 제출 전 교차 검증.
- **근거**: 과장 1건이 문서 전체 신뢰를 무너뜨림. 경계 선언이 진짜 LLM 기능의 신뢰를 만든다.

## ADR-004 · 2026-08-01 · 플레이 링크 = GitHub Pages, 프록시만 서버리스
- **결정**: 제출 플레이 링크는 GitHub Pages 정적 빌드. 평가서 프록시만 별도 서버리스 함수(CORS).
- **근거**: 제출 양식이 "GitHub Pages (링크)"를 명시. 정적 = 심사 시점 장애 표면 최소화.

## ADR-005 · 2026-08-02 · 오디오 = fal 단일 SDK + 다중 모델 경쟁 배치
- **결정**: BGM은 fal에서 모델 3종(Lyria 3 Pro / Stable Audio 2.5 / MiniMax 2.6 등) × 후보 2곡 경쟁 배치 → 스튜디오 A/B 즉결. SFX는 ElevenLabs Sound Effects v2(fal 경유). ffmpeg 심리스 루프 후처리 계승.
- **근거**: 키 1개·단일 SDK로 품질 상한 확보, 검증된 후처리 자산 재사용.
- **기각**: Suno/Udio — 품질 최상위지만 상업 라이선스 미정리(소송 진행 중). 수상작 사업화 우선협상권 고려 시 라이선스 클린 우선.

## ADR-006 · 2026-08-02 · 파이프라인 = Order-as-Data + 이벤트 소싱 + Manifest SoT
- **결정**: tidy-up의 원칙(골든 ref 앵커, 발주→검수→재발주, 스테이징→승격)은 계승하되 구현 재설계 — 발주는 타입드 데이터, 상태 전이는 이벤트 스토어 자동 기록(수동 원장 없음), 승인 에셋만 manifest 진입.
- **근거**: 셸 스크립트 난립·사람 규율 의존 제거. 문서·스태프롤 숫자를 전부 이벤트 쿼리로 도출.
- **기각**: tidy-up 도구 직접 포팅(gen-*.sh 방식).

## ADR-007 · 2026-08-02 · 골든 레퍼런스는 톤 오디션으로 확정
- **결정**: 같은 피사체(참치 초밥)를 4개 아트 톤으로 생성 → 검수 보드에서 디렉터가 1장 승인 → 그 1장이 전 에셋의 앵커.
- **근거**: 톤은 한 번 잘 잡으면 되는 최우선 크리티컬 패스이며, 반드시 디렉터 검수를 거쳐야 함(디렉터 요구사항).

## ADR-013 · 2026-08-05 · 저속 회선 로딩 전략 — 에셋 워밍업 파이프라인
- **문제**: 모바일 저속 회선에서 라운드가 넘어갈 때마다 배경·스프라이트가 뒤늦게 떴다(디렉터 리포트). 원인은 구조적 — 이미지는 **렌더되는 순간** 최초 요청이 나가므로 라운드 전환 시점이 곧 첫 요청 시점이었다. 계측(700kbps/RTT 300ms)에서 타이틀 조작 가능까지 **7.9초**, 실효 대역폭은 회선의 절반(42KB/s)에 그쳤다.
- **결정**: 6가지를 함께 적용한다.
  1. **2단계 부팅 게이트** — ①타이틀 에셋만 받고 화면 공개 ②타이틀을 보는 동안 1라운드 에셋 확보 후 시작 버튼 해제. 전체(1.8MB)를 한 번에 기다리면 저속 회선에서 30초가 넘는다.
  2. **HTML 인라인 스플래시**(`index.html#boot`) — 로딩 화면을 React 컴포넌트로 두면 로딩 화면이 JS 번들을 기다려 수 초간 암전된다. HTML+인라인 CSS만으로 그려 **529ms에 첫 페인트**.
  3. **플레이 순서대로 백그라운드 선반입** — 큐 순서가 곧 우선순위라 별도 스케줄러가 필요 없다. 라운드 진입 시 다음 테마를 명시 승격해 `?round=N` 점프도 커버(`src/assets/preload.ts`).
  4. **BGM을 임계 경로에서 제외** — BGM 1곡이 639KB로 이미지와 대역폭을 다퉜다. 제스처 전엔 어차피 소리가 안 나므로 1라운드 에셋 확보 후로 미룬다.
  5. **preload 힌트 빌드 주입**(`vite.config.ts`) — 히어로 이미지 URL이 JS 번들 안에 있어 번들 파싱(1.6초) 전엔 요청조차 못 나갔다. 해시된 산출 파일명을 찾아 `<link rel=preload>`로 심어 JS와 병렬 수신.
  6. **페이로드 감량** — 배경 webp q84→q70(992→620KB, 37%↓; 플랫 셰이딩 카툰이라 1:1 픽셀에서 구분 불가, 스프라이트는 알파 경계 때문에 q84 유지). 폰트는 CDN 통짜 Pretendard Variable **2,009KB**가 게임 이미지 전체보다 컸다 → 실제 쓰는 591자만 남긴 자체 호스팅 서브셋 **101KB**(95%↓)로 교체, 외부 CDN 왕복·장애 표면도 제거(`tools/gen-font-subset.py`).
- **결과**(동일 조건 재계측): 타이틀 등장 7.9초 → **3.3초**, 시작 가능 12.3초 → **6.7초**, 첫 페인트 2.5초 암전 → **0.5초**. 플레이 중 배경 확보가 라운드 진행보다 항상 앞선다(+3초에 3개, +20초에 8개 — 라운드당 5~8초 소요).
- **기각**: 전체 에셋 블로킹 프리로드(저속 회선 30초+), 서비스 워커 캐싱(첫 방문 심사에는 무효 — 재방문 이득뿐이라 비용 대비 효과 없음).

## ADR-012 · 2026-08-05 · 테마명 "김밥천국" → "김밥집" (상표 리스크 제거)
- **결정**: 1테마 표시명을 실존 프랜차이즈 상표인 "김밥천국"에서 일반명사 "김밥집"으로 변경. 게임 텍스트(`pipeline/texts.json` theme-gimbap)·manifest·발주 라벨·전 문서 10곳 일괄 교체. 테마 id(`gimbap`)·아트·게임플레이는 불변.
- **근거**: 참가 약관 제4조 2항이 "타인의 상표권을 침해하지 않음"을 참가자 보증 사항으로 규정하고, 제9조 2항은 그 책임을 전적으로 참가자에게 귀속시킨다. 상품류가 달라 침해 성립 가능성은 낮으나, 수상 시 주최사 우선협상권(제7조)에 따른 사업화 검토에서 반드시 재작업이 필요한 이름이며 **교체 비용이 0**이다. 표시명 외 게임 가치에 영향 없음.
- **확인**: 아트에는 상호 텍스트가 없어 재생성 불필요. 나머지 9개 테마명(카페·초밥집·택배 상하차·편의점·치킨집·빵집·세차장·붕어빵 노점·노래방)은 모두 일반명사로 검증 완료. 제출 영상에는 테마명 미노출(해당 판 평가서에 테마 줄 미출력)이라 영상 재촬영 불필요.

## ADR-011 · 2026-08-02 · AI 스태프롤 게임 내 노출 제거
- **결정**: 게임오버 화면의 "AI 알바 근무 기록" 3줄 제거. 게임은 일반 유저 대상의 게임으로만 서고, AI 협업 서사·실측 숫자(pipeline/credits.json)는 기술 문서와 영상 엔딩이 전담.
- **근거**: 디렉터 판단 — 게임 맥락에서 개발기 노출은 뜬금없고 몰입을 해침. 심사 서사는 문서·영상에서 더 정확하게 전달 가능.

## ADR-010 · 2026-08-02 · 런타임 LLM 완전 배제 — 게임은 100% 정적
- **결정**: ADR-002의 게임오버 LLM 평가서(유일한 런타임 LLM 후보)도 배제. 평가서는 빌드타임 AI 작성 문장 뱅크 + 결정적 텔레메트리 조립으로 확정. 게임은 API 키·프록시·네트워크 의존 0의 완전 정적 빌드.
- **근거**: 디렉터 판단 — 체감 가치 대비 인프라(키+프록시 서버)가 과중. 전략 검증 때도 컷 1순위였음. 심사 시점 장애 표면 0 = 실행 마찰 제로 원칙의 완성.
- **서사**: 기술 문서에 "런타임 LLM 의사결정 매트릭스"로 검토→기각 과정을 기록. 본선 48시간 확장 카드로 유지.

## ADR-009 · 2026-08-02 · 무대 정합성 원칙 — 배경은 "알바 1인칭 작업대"다
- **결정**: 모든 배경은 작업자(알바) 1인칭 시점으로, **화면 하단 40~45%가 비어 있는 연속된 작업 표면**(카운터/도마/철판/계산대)이어야 한다. 게임 타깃·소품은 그 표면 밴드(y≥~700) 위에 배치한다. 발주서 common에 구도 스펙 명문화.
- **근거**: 1차 배경(손님 시점 가게 풍경)은 게임 오브젝트가 공중에 떠 보여 배경과 게임이 분리됨 — 디렉터 반려. 게임의 서사(알바가 일한다)와 화면의 시점이 일치해야 현실감이 생긴다.
- **기각**: 손님 시점 풍경 배경(order#2 3장 반려·order#4 폐기, pipeline/rejected/ 보관).

## ADR-008 · 2026-08-02 · 아트 톤 확정 = A 팝 코믹 카툰 (tone-a-pop-comic)
- **결정**: 톤 오디션 4종 중 **A 팝 코믹 카툰**을 디렉터가 골든 레퍼런스로 지정(`pipeline/refs/style-ref.png`). 이후 모든 이미지 발주는 이 이미지에 앵커.
- **근거**: 진한 아웃라인+고채도 — 4종 중 72px 스케일 판독성 최강, 5~10초 스피드 코미디 게임의 텐션과 일치.
- **기각**: B 클레이 파스텔(대비 약함·힐링 톤), C 레트로 픽셀(전 에셋 픽셀 규칙 유지 비용), D 플랫 벡터(무아웃라인 — 복잡 배경 판독성 열세).
